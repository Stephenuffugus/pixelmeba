# tune-g2 fix round 1: P2.9 second tuning report

Scope: tools/sim-tune.ts, tools/sim-run.ts (additive), tests/tools/sim-tune.test.ts, docs/reports/tune-g2.md.
No recipe, mechanic, constant or content number was changed. The report was regenerated by the fixed tool.
Its 600 s D06 numbers are unchanged: a diff against the previous report shows only the intended columns
and tables.

## Per problem

1. **1,200 s evidence not in the repo** (two verifiers): FIXED. New `--horizon <s>` in tools/sim-tune.ts.
   The same runs continue past the D06 endpoint. Each preset gets a "supplementary horizon, 1200 s" section:
   - a per-seed table: agents, food, gains and losses by module, carriers, branches by kind, first
     branch, extinctions, hash and plain-run check;
   - living counts every 60 s from 660 to 1,200 s;
   - pooled and per-module rates, and the carrier tables;
   - branches pooled by name, and censored milestones.

   A side-by-side table closes the section. The D06 checkpoints are taken before the horizon.
   Tests: "the horizon is one more checkpoint of the same run; the D06 checkpoint is unchanged by it"
   (same checkpoint JSON and the same D06 report text with and without the horizon) and "takes the
   horizon during, at or after an extension". Every 1,200 s figure the analysis quotes is now in a table.
2. **Per-module rates for rare modules**: FIXED. The observer counts per-module gain trials (daughters
   whose parent could legally gain the module, by species). It also counts expected gains (gain-attempt
   chance ÷ the parent's number of legal gains), and does the same for losses. A new "Per-module rates"
   table at 600 s and 1,200 s gives trials, events, per trial, expected (Poisson 95 %) and per minute.
   Test: an independent recount from the birth records of the 150 s Accelerated run (trials equal,
   expected to 1e-12, rendered row). Standard 600 s: E01 1/2,896 (expected 1.0; 0–3); E03 0/2,952 (1.0;
   0–3); E05 8/13,572 (11.6; 5–19).
3. **Starch release cause** (two verifiers): FIXED. For each E01 carrier, every simulated second, the tool
   now records:
   - the outcome the sim wrote (secretionCode while Active, else the state reason);
   - whether starch is in or beside its cell (the stage's own substrate test, `starchWithinReach`);
   - whether energy is at or below the recorded threshold;
   - whether both hold.

   The report now says that by 600 s starch was never within reach (0 of 2,638 carrier-seconds) and
   energy was at or below 35 in 46.3 % (Standard) and 53.5 % (Accelerated) of them. It makes no location
   claim. Test: "tallies the recorded outcome and measures both blockers directly" (four built carriers).
4. **D06 §18 headings blurred**: FIXED (text). The pacing targets moved to "Fast enough". Repeated
   branch names and the one-card-per-60 s cap moved to "Understood". The two descriptive sections come
   first, then the four questions.
5. **Build not identified** (two verifiers): FIXED. The header now records:
   - git HEAD, from read-only `git --no-optional-locks`;
   - whether src/sim/ and content/ differ from HEAD;
   - the tool's own uncommitted paths;
   - the rule versions: simulation, evolution rules, module registry, phenotype mapping, content and
     world schema.

   The report reads: HEAD 3ebfdf585dc3…, src/sim/ and content/ identical, versions 3/1/1/1/1, schema 3.
   The analysis notes that R03 fixes simulationVersion 3, so that number never identified a build.
   Tests: "names the build and the rule versions in the header", and `run.rules`.
6. **"The tuner only observes" proves nothing** (two verifiers): FIXED. `--plain-check` re-runs every seed
   with no observer and no hooks and compares state hashes at every checkpoint (exit 2 on a difference).
   All 12 seeds agree at 600 s and 1,200 s (24 comparisons). The integrity table prints an endpoint hash
   only for extended runs. Tests: "a plain run gives the same hash at every checkpoint" (a tampered hash
   shows DIFFERS and is an integrity problem) and "prints an endpoint hash only for an extended run". The
   old renderer printed the hash twice: 2 occurrences, now 1, shown by a scratch old-vs-new script.
7. **"Chance of no gain attempt" used eligible daughters**: FIXED. The waiting-time table now has two
   columns: all daughters with the chance of no gain attempt, and gain-eligible daughters with the chance
   of no committed gain. The median wait is labelled as the wait for a committed gain. The test asserts
   the header and the row for Accelerated 130363 at 150 s (330 daughters, 316 eligible). The old renderer
   fails it. In the report, Accelerated 130363 is 0.0012 % against 0.0045 %.
8. **"1–9 carriers" left out the 2 dishes with none**: FIXED (text, three places).
9. **Bloom mechanism wording**: FIXED (text). It now says "coincides with" and gives onsets from the new
   60 s table: Standard 104729 5→34→244→547 at 600–780 s; Accelerated 155921 and 314159 later. Two dishes
   had Recyclers at 600 s and no bloom (196613, 262147).
10. **Standard waiting time used Accelerated inputs**: FIXED (text). Standard figures only: 41 gains in 120
    dish-minutes and 5 module branches, about one per 24 dish-minutes; 3 of 6 dishes by 1,200 s.
    Accelerated figures are labelled separately.
11. **"Did not measurably slow" rested on one pair**: FIXED. Seven interleaved rounds (G1 tag / G2
    Standard / G2 Accelerated, load 4.8–6.9), and process CPU time for three of them. `sim-run --perf`
    now also reports the tick loop's CPU time (`perf.cpu`, additive; test extended).

    | Build | p50 (median) | Process CPU |

    | G2 Accelerated | 4.25 ms | not compared |

    The difference from G1 in each round ran from +8.7 % to −38.8 %. The report now says "no
    difference is visible; resolution about ±10 %".
